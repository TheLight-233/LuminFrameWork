# LuminFrameWork

> **一个通用的游戏代码框架：用 .NET 10 写游戏逻辑，可接入任何游戏引擎。**
>
> ⚠️ 目前仍在开发探索阶段。

用 **.NET 10** 编写一套通用游戏代码，让它能稳定运行在 **Unity、Godot、Unreal 或任何自研引擎**之上。引擎只负责渲染与输入，游戏逻辑完全由这套框架承载，与具体引擎彻底解耦——写一次，随处运行。

---

## 为什么这样做

| 传统做法的痛点        | 这套方案的优势 |
|----------------|----------------|
| 引擎绑定语言，开发效率慢   | 直接使用 .NET 10 / 最新 C# 语法，不受引擎限制 |
| 只能调用引擎内置脚本 API | 可引用完整 .NET 生态与任意 NuGet 包 |
| 换引擎 = 逻辑全部重写   | 与引擎解耦，一次编写、多引擎部署 |
| 客户端逻辑无法在服务端复用  | 同一套逻辑可被服务端直接复用 |
| 每次构建都要编译整个引擎脚本 | 只编译游戏逻辑层，增量构建快，天然支持热重载 |
| AI 时代需要理解引擎 API 才能提效 | 钩子以静态方法形式呈现，像 CLI 一样自描述，AI 理解与调用更直接、更省 Token |

---

## 构想要点

- **LuminFrameWork 作为引擎钩子层**：把引擎能力抽象成一套跨引擎的钩子（`Unity.*`、`Godot.*`、`UE.*` 命名空间下的静态方法），供上层游戏代码统一调用，成为「引擎中立、可移植」的调用入口。
- **LuminCLR 作为运行时**：把用户用 .NET 10 写好的代码转译成 C++，以 **AOT + 解释器混合模式**编译并运行，再通过上面这套钩子接入具体目标引擎。

引用任何兼容 AOT 的 NuGet 包、使用最新的 C# 语法，不受引擎脚本版本限制；同时逻辑可被服务端复用，也天然支持开发期秒级热重载。
